# UpGrade — Project Context

> Created: 2026-08-24
> Purpose: Single source of truth for what we discussed. Read this before coding.

## 1. Vision
**UpGrade** — AI-powered learning app for anyone who is learning stuff (personal use first). User should only have to follow what AI teaches, no decisions/planning.

- **Frontend:** Flutter 3.47.1 + Dart 3.13.1 (1 codebase → Android/iOS/Web/Windows/macOS/Linux)
- **Backend:** FastAPI 0.141.1 + Pydantic 2.13.4 + Python 3.13 + uv 0.12.5 + Ruff
- **DB:** Neon Postgres (`backend/.env` → `DATABASE_URL=postgresql://...neon.tech/neondb`)
- **AI:** Groq (`GROQ_API_KEY` in `backend/.env`) + OpenCode Zen free models via `https://opencode.ai/zen/v1` (OpenAI-compatible). Tested: `hy3-free`, `laguna-s-2.1-free`, `nemotron-3-ultra-free` work; `muse-spark-1.2-contributor-free` is TUI-only (500 on API).

## 2. Core Concepts

### Subjects
User can create **multiple subjects** (e.g. "DSA", "Rust", "System Design").

Each **Subject** has MUST-HAVE DB fields:
- `what_to_learn` — what user tryna learn (required, free text)
- `goal` — user's goal for that subject (e.g. "FAANG in 3 months", "build a CLI")
- `topics` — subject-related topics (generated by AI as ordered roadmap)
- `learned / knowledge` — what topics user currently has learned and has knowledge of
- `curr_state` — derived current state from QnA (hours/week, background, deadline, etc.)

### AI Handles All The Stuff
No manual syllabus. User gives seed (`what_to_learn`), AI does the rest.

### AI Tool: `ask_question`
- AI has tool `ask_question(question, why)` — can ask tons of Qs, one by one.
- Frontend shows each Q as chat, user answers.
- Loop repeats until AI has **no assumptions** — it has `goal` + `curr_state` complete.
- Only then AI calls `finalize_subject(goal, curr_state, topics)`.
- This prevents generic roadmaps.

### Study = Follow Roadmap
After QnA, AI gives **detailed roadmap in proper order & sequence** — user only has to learn what AI teaches, step-by-step.

Roadmap = `Topics` ordered 1..N, grouped in Phases, with `order`, `prerequisites`, `est_time`, `status=locked/current/done`. Only `current` is active.

### Feed — The Main Classroom
- **Format:** X/Twitter-like tweet feed (280-char lesson + code/visual/mini-exercise). Each post sequential.
- **Rule:** Feed **only shows current topic** the user needs next.
  - Example: DSA → curr=`Stack & Queue` → feed only Stack & Queue posts until LLM marks done → then feed flips to `LinkedList` → then `Tree`. Never shows future/past together.
- **Must not be generic bullshit:** Prompt injects `goal` + `curr_state` + `what_to_learn` so Stack for "FAANG interview" ≠ Stack for "build Redis". Each feed is personalized.
- **Interaction:** Scroll = study. Per-post `Open Chat` button → opens AI chat with same `subject/topic` context → clear doubts. Chat can also mark topic done.
- **JIT (Just-In-Time):** LLM does **NOT** generate all feed at once. It generates 5-10 posts for `current` topic on demand when user opens feed. When topic done, LLM deletes old `feed_posts` and generates next batch.

### LLM Has DB Access
LLM is not dumb — it has tools that are DB queries:
- `get_current_topic(subject_id)`
- `get_user_state(subject_id)` → reads `what_to_learn, goal, curr_state, knowledge`
- `generate_feed_post(topic_id)` → writes to `feed_posts`
- `mark_topic_done(topic_id)` + `delete_old_feed(topic_id)`
- `get_feed_posts(subject_id)`

AI checks DB as source of truth, never assumes.

## 3. Database — Neon Postgres

5 tables (JIT, ephemeral feed):

```sql
users(id PK, email, name, created_at)
subjects(id PK, user_id FK → users, title, what_to_learn TEXT NOT NULL, goal TEXT NOT NULL, curr_state JSONB, status)
topics(id PK, subject_id FK → subjects, title, order INT, phase TEXT, status ENUM('locked','current','done'), est_time)
feed_posts(id PK, subject_id FK, topic_id FK → topics, content TEXT, order INT, type ENUM('lesson','code','quiz'), created_at)
topic_progress(id PK, user_id FK, topic_id FK, status ENUM('todo','done'), completed_at)
```

Indexes: `topics(subject_id, order)`, `feed_posts(subject_id, topic_id, order)`.

Flow: `Subject created (what_to_learn) → QnA loop → curr_state filled → AI generates topics → topics[0]=current → GET /feed → generate feed_posts for current → study → POST /topics/{id}/done → delete old posts → next topic=current`.
